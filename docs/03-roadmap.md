# ۰۳ — نقشهٔ راه: ۹ مرحله، هر زیرمرحله با یک مالک

اصل کار: **هیچ زیرمرحله‌ای بی‌صاحب نیست.** مالک یعنی نویسندهٔ PR و پاسخ‌دهندهٔ تست‌ها؛ نفر دوم بازبینی می‌کند.
روی گیت‌هاب این ساختار عیناً با Milestone + Issue + لیبل `owner:*` پیاده شده است.

علامت‌ها: (پ) پرهام · (ع) علی · (۲) هر دو

## مرحلهٔ ۱ — پی‌ریزی و داکیومنت ✅
- (پ) مخزن مشترک + دسترسی Write برای هر دو عضو
- (۲) README، مجوز MIT، قواعد مشارکت
- (ع) چهار سند فنی + سایت داکیومنت (Pages)
- **معیار پذیرش:** مخزن و سایت برای ارائه قابل‌اتکا باشند. ✔

## مرحلهٔ ۲ — هستهٔ Node و زمان شبیه‌سازی 🔵 جاری
- (پ) ماشین حالت سه‌نقشی + جداسازی state ماندگار/فرار
- (پ) ساعت شبیه‌سازی و حلقهٔ tick
- (پ) لایهٔ شبکه: تأخیر تصادفی + لینک‌های قابل قطع
- **معیار پذیرش:** خوشهٔ headless بدون RPC گم‌شده tick بخورد؛ تست واحد سبز.

## مرحلهٔ ۳ — انتخاب رهبر
- (پ) تایمر تصادفی + `RequestVote/VoteResponse`
- (پ) قانون «لاگِ به‌روز» برای رأی دادن
- (پ) تست واحد: تک‌رهبری + split vote
- **معیار پذیرش:** در هر لحظه دقیقاً یک Leader؛ Term اکیداً صعودی.

## مرحلهٔ ۴ — تکرار لاگ
- (پ) `AppendEntries` و heartbeat؛ `nextIndex/matchIndex`
- (پ) تشخیص تضاد و truncate
- (پ) `commitIndex` و state machine
- (۲) تست یکپارچهٔ ۱۰ فرمان با ترتیب یکسان
- **معیار پذیرش:** هر ۱۰ فرمان در همهٔ گره‌های زنده اعمال شوند.

## مرحلهٔ ۵ — تحمل خطا
- (پ) crash/restart با مرز دقیق persisted/volatile
- (پ) پارتیشن شبکه و split-brain
- (پ) تست سناریوها: مرگ رهبر، heal، step-down رهبر قدیمی
- **معیار پذیرش:** همهٔ سناریوها در تست یکپارچه سبز؛ ایمنی‌ها نقض نشوند.

## مرحلهٔ ۶ — پل WebSocket و API
- (پ) سرور asyncio و انتشار زندهٔ رویدادها
- (پ) پروتکل کنترل بیرونی: kill / submit / partition
- **معیار پذیرش:** یک کلاینت WS بدون افت رویداد متصل بماند.

## مرحلهٔ ۷ — رابط وب تعاملی
- (ع) توپولوژی SVG با انیمیشن پیام‌ها + قطع لینک با کلیک
- (ع) پنل لاگ هر گره (رنگ بر اساس Term) + event stream
- (ع) کنترل‌ها: سرعت، pause/step، submit، kill/restart
- (ع) توکن‌های طراحی، ریسپانسیو و دسترس‌پذیری
- **معیار پذیرش:** دموی ۳ دقیقه‌ای بدون خطا مستقیم از Pages.

## مرحلهٔ ۸ — تست، کیفیت و سخت‌سازی
- (پ) assertionهای ایمنی (Leader Completeness / State Machine Safety) در هر tick
- (۲) تست E2E مرورگر + WebSocket
- (ع) ممیزی عملکرد و دسترس‌پذیری رابط
- **معیار پذیرش:** سوئیت کامل سبز + چک‌لیست UX اسکیل تیک‌خورده.

## مرحلهٔ ۹ — گزارش و ارائه
- (۲) گزارش نهایی مطابق قالب درس
- (۲) اسلاید + دموی زندهٔ ۳ دقیقه‌ای
- (ع) بازبینی نهایی اسناد و سایت
- **معیار پذیرش:** ارائهٔ خشکِ بدون خطا + بوفِر کامل برای اتفاقات ناخواسته 🎯

## مدیریت ریسک

| ریسک | راه‌حل |
|---|---|
| باگ ظریف election (split-brain) | assertion ایمنی در هر tick + تست سناریو |
| وقت‌گیر شدن UI | UI مرحلهٔ ۷ است؛ موتور اول کامل و تست‌شده |
| تجمع دانش در یک نفر | هر ماژول داکیومنت دارد؛ بازبینی دوطرفه |
| اتفاق شخصی | مالک هر زیرمرحله مشخص است؛ جابه‌جایی بدون ابهام ممکن است |
