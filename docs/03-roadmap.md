# ۰۳ — نقشهٔ راه و مدیریت ریسک

روند کار ساده است: **مرحله به مرحله، بدون پرش.** هر مرحله وقتی «تمام» است که تست‌هایش سبز باشند و PR آن بازبینی شده باشد.
روی گیت‌هاب، هر مرحله یک **Milestone** و هر کار یک **Issue** است؛ همین سند، نسخهٔ مکتوبشان است.

## مرحلهٔ ۰ — پی‌ریزی و داکیومنت (✅ انجام شد)
- ساخت مخزن مشترک و دعوت هم‌تیمی با دسترسی Write
- README، مجوز، قالب‌های Issue/PR، CONTRIBUTING
- سایت داکیومنت روی GitHub Pages
- **معیار پذیرش:** مخزن و Pages برای ارائه قابل‌اتکا باشند. ✔

## مرحلهٔ ۱ — هستهٔ انتخاب رهبر (🔵 جاری)
- `RaftNode` با سه نقش و تفکیک state ماندگار/فرار
- تایمر انتخابات تصادفی؛ RPCهای `RequestVote/VoteResponse` با قانون لاگِ به‌روز
- تست واحد: خوشهٔ ۳تایی → دقیقاً یک Leader؛ سناریوی split-vote
- **معیار پذیرش:** `pytest -q` سبز؛ تنها یک رهبر در هر لحظه.

## مرحلهٔ ۲ — تکرار لاگ
- `AppendEntries` + heartbeat؛ مدیریت `nextIndex/matchIndex`
- تشخیص تضاد، truncate، محاسبهٔ `commitIndex`
- state machine و اعمال ترتیبی دستورها
- **معیار پذیرش:** ۱۰ فرمان تزریق‌شده، در همهٔ گره‌های زنده با همان ترتیب اعمال شوند.

## مرحلهٔ ۳ — تحمل خطا
- kill/restart با مرز دقیق persisted/volatile
- پارتیشن شبکه؛ سناریوهای مرگ رهبر، اقلیت/اکثریت، heal و step-down رهبر قدیمی
- **معیار پذیرش:** همهٔ سناریوهای جدول تحمل خطا در تست یکپارچه سبز شوند.

## مرحلهٔ ۴ — رابط وب تعاملی
- توپولوژی SVG با انیمیشن پیام‌ها؛ قطع لینک با کلیک
- پنل لاگ هر گره (رنگ بر اساس Term)؛ event stream زنده
- کنترل‌ها: سرعت، pause/step، submit فرمان، kill/restart
- سرور WebSocket + تست E2E
- **معیار پذیرش:** دموی ۳ دقیقه‌ای بدون خطا، مستقیم از GitHub Pages.

## مرحلهٔ ۵ — گزارش و ارائه
- گزارش نهایی مطابق قالب درس (مقدمه، طراحی، تست، نتیجه)
- اسلاید + دموی زندهٔ سناریوها
- بوفِر کامل برای اتفاقات ناخواسته 🎯

## مدیریت ریسک

| ریسک | احتمال | اثر | راه‌حل |
|---|---|---|---|
| باگ ظریف در منطق election (split-brain) | متوسط | زیاد | تست سناریو + assertion ایمنی در هر tick |
| وقت‌گیر شدن UI | متوسط | متوسط | UI مرحلهٔ ۴ است؛ موتور اول کامل و تست‌شده می‌شود |
| ناهماهنگی دو عضو | کم | متوسط | جلسهٔ هماهنگی هفتگی + خلاصهٔ مکتوب در Issue |
| اتفاق شخصی | کم | زیاد | هر ماژول برای هر دو عضو قابل‌فهم است (به‌لطف داکیومنت) |
