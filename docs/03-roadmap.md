# ۰۳ — نقشهٔ راه، ددلاین‌ها و مدیریت ریسک

**شروع پروژه:** چهارشنبه ۲۰۲۶/۱۰/۰۸ (۱۶ مهر ۱۴۰۵)
**ارائهٔ نهایی:** پنجشنبه ۲۰۲۶/۱۲/۱۷ (۲۶ آذر ۱۴۰۵)
**جلسات هماهنگی:** جمعه‌ها، ۴۵ دقیقه؛ خروجی هر جلسه یک Issue با لیبل `docs`.

> همهٔ فازهای زیر به‌صورت **Milestone** واقعی روی گیت‌هاب ساخته شده‌اند و کارهای هر فاز **Issue** دارند.

## فاز ۰ — راه‌اندازی و داکیومنت (✅ تا ۲۰۲۶/۱۰/۰۸)
- ساخت مخزن مشترک، دعوت هم‌تیمی با دسترسی Write
- README، مجوز، قالب‌های Issue/PR، CONTRIBUTING
- سایت داکیومنت روی GitHub Pages
- **DoD:** مخزن برای استاد قابل‌ارائه و Pages فعال.

## فاز ۱ — هستهٔ انتخاب رهبر (🔵 تا ۲۰۲۶/۱۰/۲۲ · ۳۰ مهر)
- `RaftNode` با سه نقش و تایمر انتخابات تصادفی
- RPCهای `RequestVote/VoteResponse` با قانون لاگِ به‌روز
- تست واحد: خوشهٔ ۳تایی → دقیقاً یک Leader، بقیه Follower
- **DoD:** `pytest -q` سبز؛ سناریوی split-vote در تست قابل‌مشاهده.

## فاز ۲ — تکرار لاگ (⬜ تا ۲۰۲۶/۱۱/۰۵ · ۴ آبان)
- `AppendEntries` + heartbeat، مدیریت `nextIndex/matchIndex`
- تشخیص تضاد، truncate، محاسبهٔ `commitIndex`
- state machine و اعمال ترتیبی دستورها
- **DoD:** ۱۰ فرمان تزریق‌شده، در هر ۳ گرهٔ زنده با همان ترتیب اعمال شود.

## فاز ۳ — تحمل خطا (⬜ تا ۲۰۲۶/۱۱/۱۹ · ۲۸ آبان)
- kill/restart با مرز دقیق persisted/volatile
- پارتیشن شبکه (کلیک روی لینک در UI / API در تست)
- سناریوها: مرگ رهبر، پارتیشن اقلیت، heal و step-down رهبر قدیمی
- **DoD:** همهٔ سناریوهای جدول «تحمل خطا» در تست یکپارچه سبز.

## فاز ۴ — رابط وب تعاملی (⬜ تا ۲۰۲۶/۱۲/۰۳ · ۱۲ آذر)
- توپولوژی SVG با انیمیشن پیام‌ها و کلیک برای قطع لینک
- پنل لاگ هر گره (رنگ بر اساس Term)، event stream زنده
- کنترل‌ها: سرعت، pause/step، submit فرمان، kill/restart
- سرور WebSocket + تست E2E
- **DoD:** دموی ۳ دقیقه‌ای بدون خطا روی GitHub Pages.

## فاز ۵ — گزارش و ارائه (⬜ تا ۲۰۲۶/۱۲/۱۷ · ۲۶ آذر)
- گزارش نهایی مطابق قالب درس (مقدمه، طراحی، تست، نتیجه)
- اسلاید + دموی زندهٔ سناریوها
- بوفِر یک هفته‌ای برای اتفافات غیرمترقبه 🎯

## مدیریت ریسک

| ریسک | احتمال | اثر | راه‌حل |
|---|---|---|---|
| باگ ظریف در منطق election (split-brain) | متوسط | زیاد | تست‌های سناریو + assertion ایمنی در هر tick |
| وقت‌گیر شدن UI | متوسط | متوسط | UI فاز ۴ است؛ موتور اول کامل و تست‌شده می‌شود |
| ناهماهنگی تقویم دو عضو | کم | متوسط | جلسهٔ هفتگی ثابت + خلاصهٔ مکتوب |
| بیماری/اتفاق شخصی | کم | زیاد | هر ماژول توسط هر دو عضو قابل‌فهم است (داکیومنت!) |
